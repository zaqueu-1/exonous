Push past ordinary UI limits—use browser capability so any region feels extraordinary: huge tables, morphing dialogs, streaming validation, cinematic transitions.

**Context rule:** “Extraordinary” depends on surface. Particles on a portfolio differ from settings—but instant optimistic saves on settings can still wow. Read personality and goals before picking technique.

### Propose before building

Highest misfire risk—do not code first.

1. Sketch **2–3 directions** (technique, ambition, aesthetic) with look/feel and trade-offs.
2. **AskUserQuestion** with options self-contained (support, perf, complexity)—structured question hides inline text until answered.
3. Build only the chosen direction.

### Iterate in the browser

Ambitious effects need visual iteration. Preview, verify, refine—multiple rounds. Close the gap between “works” and “extraordinary” with eyes, not assumptions.

## What “extraordinary” means here

Ask: **what would surprise-and-delight a user of THIS interface?**

### Visual/marketing surfaces
Sensory impact: scroll-linked reveal, shader field, cinematic transition, cursor-reactive generative art.

### Functional UI
Felt quality: View Transition from trigger to dialog; massive virtualized tables; streaming validation; springy drag-and-drop.

### Performance-critical UI
Invisible polish: huge filters without flicker; forms that never block the main thread; near-real-time editors—zero hesitation.

### Data-heavy UI
Fluid data: GPU Canvas/WebGL; morphing chart states; force layouts that settle naturally.

**Thread:** implementation exceeds typical web expectations; technique serves experience.

## Toolkit (by goal)

### Cinematic transitions
View Transitions API; `@starting-style`; spring physics (Motion, GSAP, custom).

### Scroll-linked motion
`animation-timeline: scroll()` with static fallback.

### Beyond CSS
WebGL/WebGPU; Canvas/OffscreenCanvas; SVG filter chains.

### Data at scale
Virtual scroll; GPU charts; animated data morphs (D3, View Transitions).

### Complex property animation
`@property`; Web Animations API.

### Performance ceiling
Workers; OffscreenCanvas; WASM for heavy compute.

### Device interaction
Web Audio (gesture-gated); orientation/light/geo with permission.

**Scope:** Enhances how features **feel**—not new product capabilities (collab, offline, backend).

## Discipline

Progressive enhancement mandatory—good without the enhancement.

Target 60fps; lazy-init heavy GPU/WASM; pause off-screen work; test mid-range hardware.

Polish the last 20%: easing, stagger offsets, secondary motion.

**NEVER:** jank on mid-range devices; bleeding APIs without fallback; sound without opt-in; ambition masking weak fundamentals; competing wow moments.

## Verify

Fresh viewer reaction; removal test; phone/tablet/Chromebook smooth; brand/context fit.

Extraordinary = doing what users didn’t think a site could—not merely newest API.
