Remove what does not earn its place: redundant UI, repeated information, decorative noise, cosmetic complexity.

---

## Assess

What makes it feel cluttered?

1. **Sources**
   - competing controls, duplicate info, visual clutter;
   - gratuitous color/font/size variation;
   - everything visible—no progressive disclosure;
   - borders, shadows, backgrounds without job;
   - unclear priority;
   - option overload, too many paths.

2. **Essence**
   - single primary user goal;
   - necessary vs nice-to-have;
   - hide, remove, or merge candidates;
   - the 20% that delivers 80%.

If unclear, STOP and AskUserQuestion.

**CRITICAL:** Simplicity removes obstacles to goals—not features by default. Every element must justify itself.

## Plan

- ONE outcome this surface must achieve;
- minimal elements to get there;
- what hides until needed;
- what merges or combines.

Simplification means saying no to good ideas for great execution.

## Simplify

### Information architecture

- Cut secondary actions, optional noise, repetition.
- Progressive disclosure: accordions, modals, steps.
- Merge similar actions; group related content.
- ONE primary action; few secondaries; rest tertiary or hidden.
- Say it once—no duplicate copy elsewhere.

### Visual

- 1–2 colors + neutrals, not a rainbow.
- One family; 3–4 sizes; 2–3 weights max.
- Drop decorative borders/shadows/backgrounds.
- Flatten nesting; no cards inside cards.
- Prefer spacing over card chrome.
- One spacing scale—no arbitrary gaps.

### Layout

- Simple vertical flow over complex grids when possible.
- Inline or hide sidebar content.
- Use width generously.
- Consistent alignment (left or center).
- Whitespace over packing.

### Interaction

- Fewer choices; clearer default path.
- Smart defaults; ask only when needed.
- Inline edit vs modal where viable.
- Remove a step if possible.
- ONE obvious next action.

### Content

- Halve copy twice where possible.
- Active voice.
- Plain language.
- Scannable structure.
- Essential facts only—no fluff, hedging, redundant headers.

### Code

- Dead CSS, unused components, orphans.
- Shallower component trees.
- Consolidated styles; consistent utilities.
- Fewer variants—3 often beat 12.

**NEVER:** strip needed functionality; hurt a11y; mystery minimalism; hide decision-critical info; erase all hierarchy; oversimplify genuinely complex domains.

## Verify

- Faster tasks?
- Lower cognitive load?
- Necessary features still reachable?
- Clear priority?
- Performance improved?

Document removed features: why, alternate access, feedback to watch.

Then `/ui-design polish`.
